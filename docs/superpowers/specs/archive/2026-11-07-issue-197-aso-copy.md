## なぜやるか

オーナーが #197 で引っかかっていたのは 4 つすべて (2026-11-07 の質問への回答):

1. 検索で見つからない
2. 名前だけでは何のアプリか伝わらない
3. ストアページが古く・地味に見える
4. 他のアプリと比べて差を感じた

実測 (2026-11-07):

- iTunes Search API で「ポモドーロ」「集中 タイマー」「勉強 タイマー」「作業 タイマー」(jp)、「pomodoro」「focus timer」(us) を検索すると、LeafTimer はどれも上位 50 件に入らない
- 上位アプリは名前に検索語と特徴を詰めている (例:「ポモドーロタイマー 勉強・仕事・作業用。シンプル集中タイマー」「勉強タイマー 超集中｜波音・雨音×ポモドーロ×記録」「異星フォーカス｜ドット絵の惑星育成タイマー Exocus」)
- 今の ja の値 (ASC 1.6.1 から読み戻し):
  - 名前 `LeafTimer` (30 字中 9 字)
  - サブタイトル `ポモドーロタイマーアプリ` (30 字中 12 字)
  - キーワード `ポモドーロ,タイマー,集中,生産性,仕事効率化,時間管理,勉強,作業,休憩,フォーカス` (100 字中 43 字)
  - 説明文は v1.2 時代のまま。サウンドは「雨音、川のせせらぎ、無音」だけで、BGM・葉の成長・履歴・通知・VoiceOver が書かれていない
  - プロモーション用テキストは空
- 今の en の値 (`docs/app-store-metadata.md`): 名前 `LeafTimer`、サブタイトル `Pomodoro Focus Timer`、キーワード 10 語 (`pomodoro,timer,focus,productivity,study,work,break,concentration,habit,streak`)。説明文は v1.5 で書いたもので、機能は今のコードと合っている

## ゴール

- 名前・サブタイトル・キーワードの文字数枠を使い、上の検索語で見つかるようにする
- 検索結果の 1 行 (名前 + サブタイトル) で「ポモドーロの集中タイマー」と「静かでシンプル」が伝わる
- 説明文を今の機能に合わせ、古さをなくす
- ja と en を同じ軸でそろえ、1.6.2 の提出 1 回で出す

## やらないこと

- ストア画像・プレビュー動画 (段 2)
- アプリ内の表示名 (ホーム画面のアイコン下の `CFBundleDisplayName`) は変えない
- カテゴリ・価格・年齢制限は変えない
- カスタムプロダクトページ・プロダクトページの最適化 (A/B) は使わない

## 失敗とみなすもの (アンチゴール)

- トーンが騒がしい: 「最強」「No.1」「神アプリ」などの誇大表現、記号の多用、絵文字 (ASC が ja・en とも絵文字を拒否する。`release-version-bump-check` の既知事例)
- Forest を連想させる言い回し (「木を育てる」「森をつくる」を主語にしない)。他社アプリ名をキーワードに入れない
- 事実と違う説明: 葉は **1 回のタイマーの進みに合わせて** 芽 → 若木 → 木と育つ (1.6.1 の What's New)。「続けるほど育つ」「育てた木が貯まる」のような、セッションをまたいで育つと読める書き方はしない
- 審査で弾かれる書き方: 名前・サブタイトルに価格や「無料」、他社名を入れる。キーワードの不自然な詰め込み (App Review Guidelines 2.3.7)。「For Kids」系の語 (2.3.8)

## 文言を作るときの決まり

- 名前・サブタイトル・キーワードの間で同じ語を繰り返さない (App Store は 3 つをまとめて検索対象にするので、重複は枠の無駄)
- キーワードは半角カンマ区切り、カンマの後に空白を入れない。単数・複数形は片方でよい
- ja のキーワードは ja だけで検索語を拾い切れるように作る。「日本のストアは en (U.S.) の文言も検索対象にする」は ASO の通説だが、Apple の公式ドキュメントでは確かめられなかった (2026-11-07、`app-store-localizations` のページは言語一覧のみ)。en は米国向けとして最適化し、日本での効果はおまけとして扱う (作る人の判断)
- 説明文の機能記述はコードに合わせる (`docs/app-store-metadata.md` 冒頭の決まり: 作業時間 `ItemValue.workingTimeList` 5〜60 分、休憩 `breakTimeList` 1〜10 分、サウンド `soundList`)
- 説明文の見出しは ja は【】、en は plain text。箇条書きは ja「・」、en `- `
- 候補は名前 + サブタイトルの組で 2〜3 案作り、検索結果 1 行での見え方 (端末で切れる位置) と合わせてオーナーに選んでもらう

## 出し方

1. `docs/app-store-metadata.md` に ja の name / subtitle / keywords / promotional_text を足し、ja・en の各項目を新しい文言に更新する (この doc が `asc-submission-prep` の入力元)
2. `docs/RELEASE_v1.6.2.md` を作り、What's New ja/en と提出前チェックを書く
3. ASC に 1.6.2 を作り、1.6.2 のビルドを紐付け、文言を `asc-submission-prep` で入力・読み戻す。名前・サブタイトルは「提出準備中」の 1.6.2 と一緒に提出される前提で、入力後に ASC の画面で 1.6.2 の提出物に含まれるかを確かめる (作る人の判断。食い違ったら止めてオーナーに報告)
   - ビルド: 1.6.1 では `app/` を変える PR の merge で Xcode Cloud が build 50 を作った (#196)。PR #198 も `app/` の pbxproj を変えているので同じく作られる想定。計画の最初に ASC / TestFlight で 1.6.2 のビルドがあるかを確かめ、無ければ Xcode Cloud のビルド開始をオーナーに確認してから行う
4. 提出クリックはオーナーのチャットでの指示を受けてから

## 進め方の区切り (作る人の判断)

- 名前 + サブタイトルの候補 2〜3 組と、キーワード・説明文・プロモーション用テキストの案は、まずチャットでオーナーに見せて選んでもらう。リポジトリ (`docs/app-store-metadata.md` / `docs/RELEASE_v1.6.2.md`) へは、選ばれた案だけを書く
- 説明文の機能 (BGM の曲数、履歴の項目、VoiceOver / Dynamic Type 対応など) は、書く人がコードで確かめる
- Review Notes・年齢制限は変えない

## 作る人に任せること

- 説明文の構成と長さ
- 検索結果 1 行での切れ方の確かめ方
