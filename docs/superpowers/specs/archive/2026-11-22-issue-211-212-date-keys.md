# #211 / #212 日付キーの暦固定と、0 時をまたいだときの読み直し (短い設計)

## 何のためか

- #212: アプリを前面に出したまま、タイマー停止中に 0 時をまたぐと、トップ画面の「今日 N」「連続 N」に前日の値が残る。#209 (#206) は前面へ戻るときに読み直す形で直したが、前面のまま日付が変わるケースは扱っていない。
- #211: 日付キー (`yyyy/MM/dd`) を作る・読む `DateFormatter` と前後日の計算が、端末の暦に従っている。和暦の端末では `0008/11/22`、タイ (仏暦) では `2569/11/22`、エジプト (`ar_EG`、暦はグレゴリオ暦) では `٢٠٢٦/١١/٢٢` のようにアラビア数字で保存される。暦と数字はどちらも端末のロケールで決まる (2026-11-22 に Mac の `swift` で 13 ロケールを実測)。ストア撮影用の `DebugStoreScreenshot.sampleStats` だけはグレゴリオ暦 + `en_US_POSIX` で、本番とそろっていない。

## ゴール / 非ゴール / やってはいけないこと

- ゴール
  - `UIApplication.significantTimeChangeNotification` を受けたら `loadCount()` を呼び、「今日」「連続」を今日の値で表示する。読み直すだけで記録はしないので、稼働中かどうかで分けない (plan を書くときの判断)。
  - 日付キーの書式・解析と前後日の計算を、グレゴリオ暦 + `en_US_POSIX` + 端末のタイムゾーンに固定する。入口は 1 か所にまとめる (`DateManager`)。
  - 和暦・仏暦などで保存済みのキーを、アップデート後の最初の `load()` で 1 回だけグレゴリオ暦のキーへ書き直す。
- 非ゴール
  - 開いたままの履歴画面 (`HistoryViewModel`) を 0 時に読み直すこと。
  - 保存形式 (UserDefaults の JSON 1 個) の見直し (#71)。
  - 履歴の 7 日グラフのラベル (`HistoryView.shortLabel` はキーの月日をそのまま出す) を端末の暦・数字で出すこと。和暦・仏暦は月日がグレゴリオ暦と同じなので変わらないが、ペルシャ暦・イスラム暦などの月日やアラビア数字の端末では、グレゴリオ暦の ASCII の月日 (`11/22`) に変わる。これは受け入れる (最終レビュー M-1)。
- やってはいけないこと
  - グレゴリオ暦の端末 (ほとんどのユーザー) で、保存済みの件数・連続日数が 1 件でも変わること。
  - 変換に失敗したキーを捨てること (解析できないキーはそのまま残す)。

## 進め方の候補 (既存キーの扱い)

| 案 | 内容 | 採否 |
|---|---|---|
| A | 今の端末の暦で読み、グレゴリオ暦で書き直す (1 回だけ) | **採用** (オーナーが選択、2026-11-22)。実装では「暦」ではなく「ロケール」(暦と数字の両方) で読む (plan を書くときの判断。`ar_EG` は暦がグレゴリオ暦でも数字が違うため)。グレゴリオ暦かつ ASCII 数字の端末では書き直しの結果が同じ。途中で暦の設定を変えた人のキーだけはずれるが、これは今も同じ |
| B | 年の範囲で推定 (1〜99 は令和 +2018、2500 超は仏暦 −543) | 不採用。知っている暦にしか効かず、ルールが増える |
| C | 変換しない | 不採用。和暦・仏暦のユーザーは、更新した日から過去の履歴と連続日数がつながらなくなる |

## 決めたこと

- 変換は `LocalSessionStatsRepository.load()` の中で、既存の移行 (`statsMigrated`) の後に行う。終わったことは新しいフラグ (UserDefaults の bool) で覚え、2 回目以降は何もしない。
- 変換の対象は `dailyCount` のキーと `lastSessionDate`。`totalCount` / `currentStreak` / `longestStreak` の数値は変えない。
- 書き直した結果、2 つのキーが同じになったら件数を足す。
- 書き直したキーが `2020/01/01`〜「明日」の外になるときは元のキーを残す (plan を書くときの判断)。暦を途中で変えた人のグレゴリオ暦のキー `2026/11/20` を和暦として読むと `4044/11/20` になり、そのまま書き直すと消えたのと同じになるため (2026-11-22 に scratchpad の Swift で実測)。
- 「今の端末のロケール」は引数で差し替えられるようにし、テストでは和暦・タイ仏暦・グレゴリオ暦・アラビア数字の fixture を使う。
- 既知の制限: 和暦の旧 formatter は閏日 `0002/02/29` (2020-02-29) と `0006/02/29` (2024-02-29) を読めない (defaultDate を入れた後も nil。2026-11-22 に実測)。このキーは元のまま残る。
- 旧 formatter の `defaultDate` は now の正午にする (最終レビュー I-2)。中国暦の `yyyy` は 60 年周期の中の年で、周期を補えないと紀元前の年になる。Cairo などで夏時間が 0 時に始まる日は、0 時が存在せず読めない。
- PR は 2 本に分ける。#212 (小さい) を先に、#211 を後に出す。plan は 1 本にする。
