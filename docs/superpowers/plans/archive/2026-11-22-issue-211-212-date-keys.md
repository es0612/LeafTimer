**Goal:** 前面のまま 0 時をまたいでも「今日 N」「連続 N」を今日の値で出し (#212)、日付キーをグレゴリオ暦に固定して、和暦・仏暦で保存済みのキーを 1 回だけ書き直す (#211)。

**Architecture:** #212 は `TimerViewModel` が `UIApplication.significantTimeChangeNotification` を受けて `loadCount()` を呼ぶだけ。#211 は `DateManager` に日付キー用の formatter / calendar の入口を作って全箇所をそこへ寄せ、純粋関数 `DateKeyCalendarMigration.migrate` を `LocalSessionStatsRepository.load()` から 1 回だけ呼ぶ。旧キーは「端末のロケールで作った旧来の `DateFormatter()`」で読み直す (暦だけでなく数字の種類もロケールで決まるため)。

**Tech Stack:** Swift / SwiftUI / XCTest、`make tests`、`make add-file`。

**Spec:** `docs/superpowers/specs/2026-11-22-issue-211-212-date-keys.md` (Task 2 以降は `docs/superpowers/specs/archive/` に移る)

## Global Constraints

- 日付キーの書式は `yyyy/MM/dd`、暦は `Calendar(identifier: .gregorian)`、locale は `en_US_POSIX`、タイムゾーンは `TimeZone.current`。
- `DateFormatter` を static にキャッシュしない (タイムゾーンが変わったときに古いまま残るため)。毎回作る。
- グレゴリオ暦の端末では、保存済みの `SessionStats` を 1 か所も変えない。
- 変換できないキーを捨てない (そのまま残す)。
- `totalCount` / `currentStreak` / `longestStreak` の数値は変換で変えない。
- 新規 Swift ファイルは `make add-file FILE=… TARGET=app|test` で配線し、同じ commit に含める (CLAUDE.md ルール 28)。
- ビルド・テストは `cd /Users/shinya/workspace/claude/LeafTimer/app &&` を前置し、`** TEST SUCCEEDED **` の存在と `** TEST FAILED **` の不在で判定する (ルール 1)。Bash timeout は 600000。
- PR は 2 本。#212 の PR は Task 2 で作る。#211 の作業 (Task 3〜) は、コントローラが #212 の PR を merge して `MERGED` を確かめた後に、新しいブランチで始める。plan の中で merge はしない (ルール 22)。

## Review Focus

1. 暦はグレゴリオ暦でも数字がアラビア数字のロケール (`ar_EG` など) → 旧キーは `٢٠٢٦/١١/٢٢` で保存されている。暦の種類で「何もしない」を判定せず、ロケールで読んで書き直す → Task 4 の `test_arabicDigitKeysBecomeASCII`。
2. 暦の設定を途中で変えた人のデータ (和暦のキーとグレゴリオ暦のキーが混ざる) → グレゴリオ暦のキーを和暦として読むと 4044 年になる。変換後のキーが `2020/01/01`〜「明日」の外なら元のキーを残す → Task 4 の `test_outOfRangeConversionKeepsOriginalKey`。
3. 書き直しで 2 つのキーが同じ日になる → 件数を足す → Task 4 の `test_collidingKeysAreSummed`。
4. 旧形式 (UserDefaults に日付キーを直接持つ) からの移行と、暦の変換が同じ起動で続けて走る → 旧移行の連続日数の計算は端末のロケールで読む (旧挙動のまま)。タイ仏暦の閏日 `2563/02/29` はグレゴリオ暦で読むと 3/1 にずれ、連続が 3→1 に変わる → Task 5 の `test_legacyMigrationThenCalendarConversion`。2 回目以降に再変換しないことは Task 5 の `test_conversionRunsOnlyOnce`。
5. タイマーが動いている間に日付が変わる → 通知を受けたら稼働中でも `loadCount()` を呼ぶ (読み直すだけで記録はしない) → Task 1 の `testSignificantTimeChangeWhileRunningDoesNotRecordSession`。
